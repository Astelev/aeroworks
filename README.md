# Aero Works

Minecraft 1.21.1 / NeoForge 21.1.256. Клиентский туман внутри облаков Simple Clouds 0.7.3+1.21.1.

Туман учитывает позицию **камеры**, высоту облаков, тип и границы региона, слои шума, движение ветра и анимацию градиентов. Плотность рассчитывается на CPU по формуле `cube_mesh.comp` и MIT-алгоритму psrdnoise из приложенного JAR. Просветы и промежутки между слоями остаются прозрачными; режим AMBIENT, который убирает облака вокруг камеры, не создаёт туман. Чтения данных с GPU нет.

Обычная геометрия использует штатные цвет и сферические дистанции Minecraft fog через `ViewportEvent`, которые читает и Sodium. Дальность зависит от плотности: `visibility / strength`, с сохранением более короткого штатного тумана.

Дополнительный depth-aware проход выполняется после возврата `LevelRenderer.renderLevel`, когда уже завершена обычная местность, Sable, DH и дополнительные слои. Вызовы частиц и `renderSnowAndRain` откладываются до завершения этого прохода. Их камера, матрицы и параметры штатного fog сохраняются в момент исходного вызова, затем эффекты рисуются на итоговой сцене. Это позволяет охватить туманом все чанки и сохранить дождь/снег перед облаками. Порядок solid/translucent частиц и погоды сохраняется; эффекты рисуются один раз. Проекции Minecraft и DH хранятся отдельно.

Для DH откладывается штатный composite облаков до этого заключительного прохода. Непрозрачный цвет облаков и weighted transparency смешиваются с готовым изображением только перед ближней геометрией; сравниваются восстановленные расстояния из разных проекций. Это исправление направлено на дефект Sodium 0.8.x, при котором поздние чанки перекрывают ранее нарисованные облака. Экранный туман остаётся для DH и остальных рендереров, обходящих Minecraft fog. DH не становится обязательной зависимостью. Совместимость с Sodium 0.8.13 и Sodium Extra 0.9.3 пока требует проверки в игре.

Финальное копирование использует собственный `cloud_fog_copy` с заменой цвета (`ONE, ZERO`), а результат fog-pass имеет alpha=1. Альфа исходного main target не означает видимость сцены: небо и DH могут содержать корректный RGB при alpha=0. Ванильный `blit` со смешиванием `SRC_ALPHA` в очищенный main target стирал такие части изображения. Тесты проверяют оба прохода, включая нулевую и частичную альфу исходной сцены, вне облака и внутри него.

В воде, лаве и рыхлом снегу используются штатные эффекты. Эффект не увеличивает видимость уже затуманенной сцены. Обработчики и миксины загружаются только на клиенте. Состояние и ресурсы сбрасываются при выходе, смене мира и перезагрузке ресурсов; framebuffer и проекция восстанавливаются перед отрисовкой руки.

## Настройки

После первого запуска: `config/aste_aeroworks-client.toml`.

```toml
[cloud_fog]
enabled = true
# Дальность полной непрозрачности в плотном облаке, в блоках.
visibility = 24.0
# Ширина перехода по значению плотности шума.
boundary_width = 0.15
# Положительное значение включает туман раньше, в разреженной кромке облака.
density_offset = 0.0
# Время сглаживания в тиках, 0 отключает сглаживание.
transition_ticks = 3.0
# Раннее появление на внешней кромке без изменения полной плотности.
edge_density_margin = 0.15
# Серый цвет: яркость на кромке и внутри, относительно освещения облаков.
edge_fog_brightness = 0.9
dense_fog_brightness = 0.65
```

Для более раннего и быстрого срабатывания попробуйте `density_offset = 0.1`, `boundary_width = 0.05`, `transition_ticks = 1.0`. Для более густого тумана уменьшите `visibility`, например до 16. Теперь слабая плотность меняет прозрачность итогового тумана, а не смешивает дальность 24 блока с многокилометровой дальностью прорисовки.

При смене мира и дальних телепортациях состояние сбрасывается. Внутри закрытого самолёта/помещения эффект тоже работает: проверяется облако в позиции камеры, герметичность кабины пока не моделируется.

## Сборка и зависимости

`./gradlew build` (Windows: `gradlew.bat build`), JDK 21. Сборка использует JAR Simple Clouds из `libs`, API 1.4-1.21.1 и CrackersLib 1.21.1-0.4.6 из Maven автора. Для запуска клиента разработки Simple Clouds и CrackersLib подключены через `localRuntime`; API поставляется внутри Simple Clouds. При обычной установке установите Simple Clouds и CrackersLib отдельно — Aero Works не включает их в свой JAR.

Create лежит в `libs`; API Sable подключён для серверного ветра. Сборка нацелена на NeoForge 21.1.256, как основная сборка пользователя.

`check` запускает 15 проверок периодичности шума, границ/пустот/слоёв облака, ветра, плавности при разном FPS и чувствительности, ранней кромки, серого цвета и порядка отложенных эффектов. CI также запускает `python3 scripts/test_cloud_fog_shader.py`: 28 проверок фактического fragment shader на программном OpenGL (Mesa/EGL), включая обычную геометрию, разные проекции Minecraft/DH и прозрачность при слабом облаке. Проверки не заменяют запуск полной сборки Minecraft.

## Проверка в игре

1. Полёт в плотное облако: дальность уменьшается примерно до 24 блоков, цвет соответствует облаку.
2. Выход из облака, полёт через просвет и выше/ниже слоёв: видимость восстанавливается.
3. Проверить движущееся облако, DEFAULT и SINGLE, вид от третьего лица, день/ночь и грозу.
4. Проверить воду/лаву, слепоту, смену измерения, отключение `cloud_fog.enabled` и `renderClouds` Simple Clouds.

Алгоритм совпадает с непрерывным полем шума Simple Clouds, но сам мод рисует облако кубическими ячейками и обновляет mesh с задержкой. Поэтому на поверхности возможна погрешность в несколько блоков; она смягчается переходом. Сторонние шейдерпаки и комбинация версий Sodium/Sable/Distant Horizons требуют проверки в игре: здесь протестирован shader, а полный игровой клиент не запускался.

## Идентификатор мода

ID Aero Works — `aste_aeroworks`. Имя JAR после сборки: `aste_aeroworks-1.0.0.jar`. Старый `aeroworks-1.0.0.jar` нужно убрать из папки `mods` перед установкой нового. ID `aeroworks` принадлежит другому моду, который могут требовать Gadgets ’n Gizmos и Create Thrusters; Aero Works не заменяет эту зависимость. Если ранее менялись параметры нашего тумана, перенесите их из `aeroworks-client.toml` в `aste_aeroworks-client.toml`.

Новые настройки `edge_density_margin`, `edge_fog_brightness`, `dense_fog_brightness` автоматически добавляются и в существующий конфиг. Расширенная кромка начинается раньше, но достигает полной силы в той же точке плотности, что и раньше; `visibility` и верхняя граница силы остаются прежними. Цвет обоих путей рендеринга одинаков: яркость облаков переводится в серый и умножается на плавный коэффициент от 0.9 до 0.65 по силе тумана.

При выборе расстояния тумана пиксель обычной поверхности имеет приоритет над смешанным буфером DH/облаков. DH используется для пикселей без обычной поверхности, а реально нарисованное непрозрачное облако перед поверхностью может перекрыть её. Скрытая LOD-геометрия не должна менять туман поверх обычного чанка. Три дополнительные OpenGL-проверки сравнивают туман земли при изменении глубины скрытого LOD и сохраняют туман на видимом LOD без обычных чанков.

Туман применяется отдельно к фону и слоям облаков. Глубина близкой грани облака больше не используется как расстояние до неба за ней. При полной силе тумана внутренние непрозрачные/прозрачные грани облачного mesh переходят в серый цвет; видимость близкой земли не меняется. Прозрачные облака учитываются и над небом с пустым depth buffer. Шесть новых OpenGL-проверок покрывают эти слои и отрисовку передних осадков/частиц после тумана.

CI проверяет новую точку внедрения по реальному байткоду `LevelRenderer` из mapped JAR NeoForge, включая дополнительные аргументы Frustum и Predicate у ParticleEngine.render. Это проверка исполняемого места вызова, а не только компиляции Java.

Очередь эффектов очищается в начале кадра и при сбросе ресурсов. Повторный вызов завершения кадра не рисует туман или эффекты второй раз. Проверки Java включают позднюю геометрию между исходными вызовами частиц, сохранение порядка эффектов, обход очереди, незавершённый кадр и ошибку fog-pass. CI сверяет точки перенаправления ParticleEngine.render и renderSnowAndRain с mapped NeoForge 21.1.256. Полный игровой клиент с Sodium/Sable/DH здесь не запускался.

## Базовый физический ветер

Sable **2.0.6**; учтён **Create Aeronautics Lift Patch 1.1.0** (его внутренний modId `ldfix`, версия в metadata — `1.0.0`). Конфиг: `config/aste_aeroworks-common.toml`:

```toml
[wind]
enabled = true
velocity_x = 8.0
velocity_y = 0.0
velocity_z = 0.0
# Множитель подъёмной силы и сопротивления парусов/крыльев.
sail_pressure_coefficient = 1.0
```

Скорости в блоках/сек, в мировых осях: +X восток, +Y вверх, +Z юг. По умолчанию используется погодное поле: поверхностный ветер около 2–3 блоков/с в ясную погоду, высотный около 8, с усилением в дождь и грозу. Прежний постоянный ветер включается через `[wind.field].dynamic=false`; тогда работают `velocity_x/z`. Вертикальный ветер добавляется горными потоками и турбулентностью в динамическом режиме; `velocity_y` сохранён для чтения старых конфигов и игнорируется. Атмосферное давление и отсутствие атмосферы по-прежнему учитывает Sable. Нужны серверная установка мода и паруса Create либо другие блоки с API `BlockSubLevelLiftProvider`. Голые корпуса не получают дополнительную силу. Это физический ветер; облака и частицы пока не меняют своё движение.

Перед каждым вызовом аэродинамики подставляется `v_body - v_wind`. Вращательное движение точки паруса остаётся штатным: `v_body + omega × r - v_wind`. Меняется только аргумент скорости в двух местах `ServerSubLevel.prePhysicsTick`: поверхности самой физической конструкции и вложенных Create-контрапций, в том числе подшипников. Общая скорость тела не изменяется: плавучесть, остальные блоки и следующие паруса получают исходные данные.

По умолчанию Aero Works теперь вычисляет силы пассивной квадратичной моделью через две существующие точки вызова Sable (обычные и вложенные поверхности). Скорость ветра вычитается в мировых координатах; затем учитывается вращение вокруг центра масс и выполняется переход в локальные координаты аппарата. Дополнительного расчёта сил Lift Patch в этом режиме нет. Его множители lift/drag и оба ограничителя продолжают применяться автоматически. При `aerodynamics.conservative_surfaces=false` вызывается исходный метод поверхности, в том числе заменённый Lift Patch. Нулевой/отключённый ветер не отключает исправление физики полёта.

`WindFields.sample(WindSample, Vector3d)` — отдельная точка выборки поля ветра. `WindSample` содержит уровень, мировую позицию физического тела (`logicalPose.position`), время в секундах и runtime id для выбора подготовленного сервером погодного снимка. Старый конструктор без id сохранён; он использует ясную погоду, пока идентичность тела неизвестна. Поле выбирается один раз за физический шаг тела; все его поверхности, включая вложенные контрапции, используют общий поток. `WindFields.setProvider(WindField)` позволяет позже заменить постоянное поле функцией высоты, биома, облаков или областей мира, не меняя интеграцию с физикой. Это приближение для пространственно неоднородного ветра: большая конструкция пока получает поток в одной опорной точке. При развитии поля можно добавить ограниченное число пространственных групп, не возвращая запрос на каждый парус. Провайдер вызывается из физического расчёта, должен быть потокобезопасным, не изменять мир и использовать подготовленные снимки для данных, недоступных на физическом потоке. Неполные векторы обнуляются перед выборкой, NaN/Infinity отбрасываются.

При сборке compile classpath получает Sable и его вложенные API-библиотеки из JAR; они не упаковываются в Aero Works. Sable и Lift Patch добавлены в localRuntime разработки. Для теста с Create установите Create и его зависимости в dev-сборку. `testWind` запускает 12 проверок кинематики/провайдера, включая общий поток, встречный ветер, боковой/вертикальный поток, неизменность скоростей, вращение и мировые координаты вложенных парусов. CI сверяет обе точки вызова и сигнатуру метода Lift Patch по байткоду. Полный запуск Minecraft и физика парусов в игре ещё требуют проверки.

Проверка в игре: соберите свободную физическую платформу с вертикальным парусом, обращённым поперёк оси X; сравните `velocity_x=8`, `-8`, `0`. Разнесённые паруса могут давать момент и поворачивать конструкцию. Затем проверьте повёрнутое крыло и парус на вложенном подшипнике. Итоговое ускорение зависит от массы, площади, ориентации, давления и настроек Lift Patch.

## Оптимизация ветра и тумана

Вместо `ModifyArgs` с обёрткой и несколькими новыми векторами на каждом парусе используются типизированное перенаправление и переиспользуемые векторные буферы на физическое тело. Один запрос поля и одно вычитание скорости на шаг; в цикле поверхностей нет новых объектов Aero Works. Кэш сбрасывается на каждом `prePhysicsTick`, а не игровом тике. Контрапции без аэродинамических поверхностей не запрашивают ветер. Тест с 20 000 обращений за два шага проверяет ровно две выборки и общий объект скорости. Sable по-прежнему считает подъёмную силу/сопротивление каждой поверхности: его группировка предназначена для отображения сил. В исправленной модели силы и моменты описаны в разделе «Аэродинамика и двухсторонние управляющие паруса»; исходные формулы доступны через переключатель совместимости.

Плотность тумана проверяется адаптивно: первая выборка немедленная, затем 0.5–5 раз/с. Резкое изменение сырой плотности (>=0.1) или видимой силы (>=0.2) назначает следующую проверку через 0.2 с. Почти неизменная плотность увеличивает интервал вдвое до 2 с. После подтверждения полного тумана интервал не короче 1 с, даже если шум внутри него заметно меняется. Обычное движение не обходит ограничение частоты. Смена мира, телепортация дальше 128 блоков и откат времени сбрасывают расписание. Вход в диапазон возможных высот также вызывает немедленную выборку. На стабильной сцене при 120 FPS за десять секунд тест выполняет не более шести выборок вместо прежних 200.

До поиска региона камера сравнивается с объединённым диапазоном высот всех доступных типов облаков. Диапазон берётся из metadata слоёв и включает отрицательные смещения относительно базовой высоты; кэш обновляется раз в игровую секунду. Ниже нижней и выше верхней границы не выполняются ни поиск региона, ни упаковка, ни шум. Пустой индекс типов при синхронизации консервативно отключает отсечение. Сглаживание, цвет и штатный fog обновляются каждый кадр. Упакованные слои переиспользуются и обновляются раз в игровую секунду для правок на месте. Выход из мира и перезагрузка ресурсов сбрасывают кэши. Цена редких проверок — обнаружение новой границы может задержаться до 2 с на ранее стабильном участке; после первого изменения частота автоматически растёт. Это число вычислений, не измерение FPS.

Отложенные эффекты делят один снимок восстанавливаемого состояния OpenGL на всю очередь. Исходные эффекты больше не читают неиспользуемые framebuffer/viewport. При трёх эффектах это сокращает чтения состояния драйвера в `DeferredEffectState` с 72 до 39 на кадр; порядок, матрицы и восстановление состояния остаются прежними. Инверсия проекции переиспользует матрицу. Shader пропускает прозрачные буферы для пикселей, полностью закрытых плотным туманом. Полноэкранные проходы сохранены для корректной геометрии DH, неба и облаков; их стоимость не устранена. Реальные FPS и фризы нужно сравнить на той же сцене в полной сборке.


`[wind].sail_pressure_coefficient` в `config/aste_aeroworks-common.toml` задаёт множитель аэродинамического давления: `1.0` сохраняет прежнюю силу, `0.1` уменьшает её в десять раз, `0.0` отключает аэродинамическую силу парусов/крыльев. Диапазон 0–10, значение по умолчанию 1. Коэффициент линейно масштабирует заданные силы и моменты подъёмной силы и сопротивления, включая движение конструкции в неподвижном воздухе; скорость ветра и общая физическая длительность шага не меняются. Это эквивалент множителя давления в формулах Sable 2.0.6 и Lift Patch 1.1.0: только аргумент интегрирования аэродинамики умножается на коэффициент, прочие силы и контроллеры получают исходный шаг. Конфиг читается один раз на тело за шаг; повторных запросов поля, векторов или второго расчёта аэродинамики на парус не добавлено.


## Аэродинамика и двухсторонние управляющие паруса

```toml
[aerodynamics]
conservative_surfaces = true
attached_flow_angle_degrees = 30.0
separated_flow_angle_degrees = 45.0
attached_flow_drag_fraction = 0.1
```

По умолчанию исправляется направление собственной подъёмной силы, но сохраняется нормальная сила давления на парус. Это существенно для Simulated `SymmetricSailBlock`: у него `sable$getLiftScalar() = 0` и `sable$getParallelDragScalar() = 1.75`. Его управляющее воздействие полностью создаётся **нормальным сопротивлением**, которое должно действовать вдоль нормали поверхности. Перенос этой силы вдоль скорости убирал управление и увеличивал продольное торможение. Теперь при обратном отклонении руля меняется знак поперечной силы и момента; переворот знака нормали сам по себе не меняет поведение двухстороннего паруса.

Скорость точки паруса относительно воздуха — `u = v - wind + omega × r`, где `r` — плечо от центра масс. Для вложенных контрапций точка и нормаль сначала переводятся в координаты тела. Подъёмная сила, заданная liftScalar обычного крыла, проецируется перпендикулярно потоку и не совершает работы. При `V = |u|`, единичной нормали `n`, `s = dot(n,u/V)` и `vn = dot(n,u)` номинальные силы равны:

- `|Lift| = rho * liftScalar * liftTuning * softcap(V² * (1-s²), liftSoftCap)`;
- `Normal = -rho * parallelDragScalar * parallelDragTuning * sign(vn) * softcap(vn², normalDragSoftCap) * n`;
- `GeneralDrag = -rho * directionlessDragScalar * directionlessDragTuning * V * u`;
- `softcap(v², cap) = v² / (1 + v²/cap²)`.

Оба ограничителя Lift Patch **применяются всегда**, включая liftSoftCap. Старый ключ Aero Works `use_lift_patch_softcaps=false` больше не используется, править его вручную не нужно. Без Lift Patch пределы lift/normal равны 40/50. Коэффициенты и пределы установленного Lift Patch читаются один раз на тело/подшаг; 0 у предела безопасно выключает его ветвь. Силы квадратичны при небольших скоростях и насыщаются выше soft cap, как и предполагалось в Lift Patch. Давление берётся из общей высотной функции в мировой позиции поверхности. Знаковая конвенция собственной lift сохраняется: положительное направление равно минус нормали, спроецированной поперёк потока. Добавлены рост сопротивления и отдельное падение собственной lift одностороннего крыла после критического угла.

На малых углах нормальное давление разлагается на поперечную и продольную составляющие. Поперечная сохраняется полностью, в том числе у двухсторонних парусов с `liftScalar=0`. Продольная до `attached_flow_angle_degrees` (30° к плоскости поверхности) умножается на `attached_flow_drag_fraction` (0.1). До `separated_flow_angle_degrees` (45°) этот множитель плавно возвращается к 1 через smoothstep от абсолютного синуса угла. После второго порога действуют прежние силы. Это работает с обоих направлений обдува и при перевороте нормали. При неверном порядке порогов второй берётся как первый + 0.1°. Значение доли 1 возвращает прежнее нормальное давление; для отключения падения собственной lift также установите `stalled_lift_fraction=1`. Общее сопротивление не уменьшается.

Сохранённая часть поперечного давления добавляется к консервативной lift, остаток нормального давления остаётся диссипативным. Поэтому поворот руля сохраняет номинальную поперечную силу, но меньше отнимает энергию на малом угле. Фактическая потеря скорости также зависит от вращения аппарата, ветра, других источников сопротивления и обмена поступательной и вращательной энергией. Soft cap собственной lift и нормального давления сохранены. После первого углового порога собственная lift одностороннего крыла дополнительно падает: за 5° плавно до 10% прежнего значения. Нормальное давление и его поперечное воздействие, включая двухсторонние рули, этим множителем не изменяются. Это упрощённая модель сваливания, без CFD.

`directionlessDragTuning` — общее сопротивление движению; его можно уменьшать независимо. `parallelDragTuning` — нормальное давление, которое также даёт двухсторонним парусам управляющее воздействие. Если обнулить оба коэффициента, симметричные паруса не создают ни сил, ни моментов. Если обнулить только normal, такие рули перестанут работать, что соответствует устройству исходного паруса. Отдельное демпфирование Sable `universal_drag` и сопротивление других механизмов не являются этими коэффициентами и Aero Works их не меняет.

**Общая нормировка скоростей аппарата удалена.** Вместо неё один совместный расчёт midpoint за подшаг интегрирует движение всех обычных и вложенных поверхностей. Собственная lift представлена кососимметричным оператором, а нормальное/общее сопротивление — физическими диссипативными операторами в точках парусов. Решается система размера 6 с массой и тензором инерции тела. Поэтому при нулевом сопротивлении подъёмная сила сохраняет суммарную поступательную и вращательную энергию даже при конечном шаге; добавочного глобального коэффициента торможения нет. При этом поворот, изменение направления траектории и обмен энергии между вращением и поступательным движением остаются физическими эффектами. Диагностические группы показывают номинальные силы в исходной точке шага.

В неподвижном воздухе аэродинамика не является двигателем: снижение переводит высоту в скорость, набор высоты тратит скорость, физическое сопротивление отнимает энергию. Ветер и восходящие потоки остаются внешними источниками энергии. Для проверки планирования временно отключите ветер и турбулентность. `conservative_surfaces=false` возвращает исходный метод Sable/Lift Patch. Численные проверки включают типичные коэффициенты симметричного паруса, отклонение/реверс руля, переворот нормали, нулевые коэффициенты drag, сохранение энергии при lift без drag, ограничение lift, несколько поверхностей и недиагональный тензор инерции. Буферы переиспользуются; в цикле парусов нет выделения новых объектов. Полноценный полёт в Minecraft здесь не проверялся.

## Настраиваемая атмосфера Sable и Lift Patch

В `config/aste_aeroworks-common.toml` добавлена секция:

```toml
[atmosphere]
enabled = true
dimensions = ["minecraft:overworld"]
reference_height = 64.0
scale_height = 1024.0
fade_start_height = 3072.0
ceiling_height = 4096.0
```

`reference_height` — абсолютная мировая высота Y, на которой относительная плотность равна 1. `scale_height` — подъём, уменьшающий её в e раз. До начала финального перехода используется `density = min(1.5, exp((reference_height - Y) / scale_height))`. Начиная с `fade_start_height` эта плотность дополнительно умножается на `1 - smoothstep(fade_start_height, ceiling_height, Y)`; на `ceiling_height` и выше — точный ноль. Плотность непрерывна; первая производная совпадает в начале финального перехода и обращается в ноль у вакуума. Верхняя граница не связана с высотой строительства мира.

По умолчанию относительная плотность около 0.794 на Y=300, 0.646 на Y=512, 0.392 на Y=1024 и 0.144 на Y=2048. Отрицательные высоты не дают бесконечного роста: сохранён потолок относительной плотности 1.5. Требуется `reference_height <= fade_start_height < ceiling_height` и положительный `scale_height`. При неверном сочетании параметров записывается предупреждение и сохраняется предыдущий корректный профиль. Настройки кэшируются при загрузке/изменении общего конфига; в расчёте поверхностей нет новых объектов или чтений конфига.

В Sable 2.0.6 `DimensionPhysics.createDefault` строит высотную кривую давления до `dimensionType.minY + dimensionType.logicalHeight`, заканчивая её нулём. Поэтому штатная атмосфера обрывается около верхней границы измерения. Наш mixin заменяет только вызов `BezierResourceFunction.evaluateFunction(Y)` внутри `DimensionPhysicsData.getAirPressure`. Базовое давление измерения по-прежнему умножается на новую кривую: измерение с базовым давлением 0 остаётся вакуумным. В выключенном режиме и вне списка `dimensions` вызывается исходная кривая. Это замена старой высотной функции, а не умножение уже обнулённого у Y≈300 результата. Сам mixin атмосферы не меняет формулы сил. Новая пассивная модель также использует эту общую функцию давления.

Проверка реального байткода обоих приложенных JAR подтверждает: одна выборка давления линейно умножает **нормальное сопротивление, ненаправленное сопротивление и подъёмную силу**. Падают все три, а не только lift. Таким образом, при прежней скорости лететь сложнее, а аэродинамическое сопротивление поверхностей меньше. При квадратичном росте подъёмной силы в обычном диапазоне снижение плотности вдвое требует примерно sqrt(2) прежней скорости для той же силы. Для lift и нормальной части drag сохраняется насыщение `v² / (1 + v² / cap²)` с пределами из Lift Patch. Поэтому скоростью нельзя компенсировать произвольно низкую плотность; liftSoftCap по-прежнему ограничивает рост подъёмной силы.

**Общее сопротивление не равно только сопротивлению крыльев.** Sable отдельно передаёт `universal_drag` в `PhysicsPipeline.init` при инициализации мира, без зависимости от давления/высоты (штатный default — 0.09). Этот глобальный механизм демпфирования сохранён и не становится слабее на высоте. Кроме того, винты Sable тоже запрашивают давление: разрежение может ослаблять их тягу. Поэтому снижение сопротивления крыльев подтверждено, но безусловный рост максимальной скорости любого самолёта не гарантируется: результат зависит от двигателя, демпфирования и soft caps. Новая кривая влияет на всех потребителей `getAirPressure`, в том числе винты и плавающие блоки, а не только паруса. Коэффициент `[wind].sail_pressure_coefficient` продолжает отдельно масштабировать силы поверхностей.

`testAtmosphere` проверяет 7 сценариев: нормировку, работу выше старого потолка, монотонность, непрерывность/касательные перехода, пользовательские высоты, точный вакуум и некорректные настройки. `scripts/check_atmosphere_hooks.py` сверяет высотную точку внедрения, сохранение базового давления, три умножения сил на давление в Sable и Lift Patch и отдельную инициализацию universal drag по реальным JAR. Игровой запуск и сравнение поведения самолётов здесь не выполнялись.


## Погодное зональное поле ветра

В `config/aste_aeroworks-common.toml`:

```toml
[wind.field]
dynamic = true
zone_size = 512.0
surface_height = 64.0
maximum_height = 250.0
surface_clear_speed = 2.5
surface_rain_speed = 4.0
surface_storm_speed = 6.0
aloft_clear_speed = 8.0
aloft_rain_speed = 12.0
aloft_storm_speed = 18.0
fallback_direction_interval_seconds = 360.0
weather_direction_interval_multiplier = 1.0
transition_seconds = 15.0
cloud_deviation_degrees = 15.0
```

Все скорости — блоки/сек, все высоты — абсолютные мировые Y. Между Y=64 и Y=250 направление и скорость плавно переходят от поверхностного к высотному слою. Выше Y=250 высотный множитель не растёт. Это выбор высоты без поиска рельефа: на высоких горах ветер тоже относится к высотному слою. Случайные изменения скорости в пределах ±15% дают около 2.1–2.9 блоков/с у нижнего слоя в ясную погоду. Коэффициент давления на паруса и высотное разрежение атмосферы продолжают действовать отдельно; скорость воздуха не равна силе на крыло.

Каждый узел сетки имеет воспроизводимую последовательность случайных целей от seed мира/измерения и координат; соседние узлы и соседние моменты времени смешиваются smoothstep. Сетка не создаёт блоков, чанков или постоянных объектов зон. Направления поверхностного и высотного слоёв отдельные; верхний следует фактическому перемещению массива Simple Clouds с суммарным отклонением до `cloud_deviation_degrees` от зонального рисунка и типа массива (каждый вносит не более половины этого угла). При отсутствии движения массива используется его заданное направление, а для SINGLE/отсутствующего массива — направление видимого движения шума, противоположное изменению scrollX/Z. `CloudManager.calculateWindDirection()` не используется как подмена фактического перемещения. Если облака неподвижны полностью, направление берётся из seed. Горизонтальная часть поля дополняется вертикальными потоками и локальными порывами турбулентности, описанными ниже.

Тип облака, горизонтальная интенсивность осадков, `includesThunder` и `storminess` берутся из Simple Clouds **в позиции тела**, а не камеры или отдельного паруса. Дождь/гроза усиливают оба слоя; при недоступной погоде SC используется штатная погода мира. Смена id типа массива меняет целевые повороты обоих слоёв даже при одинаковой категории погоды и скорости; фактический ветер плавно догоняет цель. Отдельно продолжаются случайные зональные повороты. Их период привязан к среднему диапазону `CloudSpawningConfig.getSpawnInterval` с учётом скорости счётчика генератора (`max(1, ceil(cloudSpeed))`) и настраиваемого множителя. Это согласование масштаба времени, не предсказание точной даты фронта. Без расписания берётся fallback 360 секунд. При смене периода интегрируемая фаза не сбрасывается.

На серверном потоке погодные данные обновляются примерно раз в секунду на активное физическое тело с парусами/контрапциями. Лимит — 16 обновлений за тик, с обходом по кругу; при более чем 320 активных телах обновление может быть реже. Удалённые тела удаляются из следующего снимка; карты снимков не изменяются после публикации. Между снимками ветер вычисляется плавно по времени. В физическом потоке — только чтение снимков, простая математика сетки и переиспользуемый выходной буфер; нет обращений к CloudManager, шуму, генерации чанков или клиентскому renderer. Интеграция сохраняет одну выборку поля на тело за физический подшаг, включая вложенные поверхности. Изменения погодной цели во время перехода начинаются с текущего значения. Экспоненциальное сглаживание даёт около 95% реакции за transition_seconds; повторные обновления направления движущихся облаков не растягивают этот срок. При выходе из мира/остановке сервера кэш очищается.

Simple Clouds и CrackersLib теперь обязательны на обеих сторонах: сервер получает погоду из собственного CloudManager. Пользовательский `WindFields.setProvider` сохранён; результат допускает все три оси. Постоянный режим доступен для сравнительного теста. Указанные скорости — настраиваемые стартовые значения для балансировки, не измеренные в игре пределы.

`testZonalWind` добавляет 14 проверок: скорости нижнего слоя, усиление при погоде, высотный предел, согласование с облачным направлением, различия зон, непрерывность на положительных/отрицательных границах сетки и во времени, прерывание перехода, реакция на новый тип массива, самостоятельные случайные повороты, воспроизводимость, неверные настройки противоположные направления слоёв и независимость времени реакции от повторных обновлений направления облаков. CI дополнительно сверяет реально используемые серверные методы/координаты/направления и weather API по приложенному Simple Clouds 0.7.3. Полный игровой запуск ещё требуется.


### Вертикальные потоки и турбулентность

В динамическом режиме ветер теперь трёхмерный. Горные потоки привязаны к сетке опорных точек рельефа: высота поверхности не ниже Y120 и горный биом либо перепад от 20 блоков на соседних пробах. Диаметр по умолчанию 100 блоков, центр медленно смещается в пределах 15 блоков, скорость до ±4 блоков/сек. Средняя высота столба над землёй 500 блоков меняется на ±20%; края, низ и верх плавные. Знак потока устойчив для каждой опорной точки, сила и положение меняются со временем. Перекрытие столбов не увеличивает скорость без ограничения.

Рельеф читается **только из уже загруженных чанков**. Каталог общий для мира, до 32 проверок опорных точек на тик; не найденные/незагруженные точки повторяются не чаще раза в 5 секунд. Эти потоки не создают билетов чанков и не вызывают генерацию.

При движении через фактическую плотность слоя Simple Clouds самолёт может получить собственный эпизод турбулентности. По умолчанию вероятность 30% на 100 блоков пути в плотном облаке, в полной грозе вдвое выше. Эпизод сопровождает аппарат 100–300 блоков пути, в том числе после выхода из облака, затем действует дистанция отдыха 150 блоков. Вход и выход сглаживаются на 10 блоках. При мировой скорости аппарата ниже 6 м/с (полный модуль скорости, включая вертикальную составляющую) активный эпизод прекращается на ближайшем серверном тике; его порывы и вращающий момент исчезают, камера получает прекращение тряски очередным визуальным пакетом (до 0.25 с). При такой скорости новые эпизоды не начинаются. Прерванная турбулентность не возобновляется после разгона: действует обычная дистанция отдыха 150 блоков, которая отсчитывается только при скорости не ниже порога. При 6 м/с и выше эпизод заканчивается по пройденному расстоянию. Скачок позиции свыше 256 блоков за тик сбрасывает состояние.

Порывы до 3.5 блоков/сек быстро меняют направление каждые 0.4 секунды. Покачивание добавляет общий случайный момент пропорционально количеству аэродинамических поверхностей, включая вложенные контрапции; давление атмосферы и `sail_pressure_coefficient` масштабируют момент. Завихрения и отдельные силы на каждый парус не моделируются. Плотность облаков читается не чаще раза в секунду на аппарат, только в допустимом диапазоне высот; общий лимит погодных обновлений — 16 на серверный тик. Физический шаг использует опубликованное состояние и один общий расчёт ветра/момента.

Настройки `aste_aeroworks-common.toml`:

- `[wind.vertical]`: `enabled`, `diameter`, `spacing`, `drift_radius`, `drift_period_seconds`, `minimum_mountain_height`, `minimum_relief`, `column_height`, `maximum_vertical_speed`.
- `[wind.turbulence]`: `enabled`, `chance_per_100_blocks`, `minimum_distance`, `maximum_distance`, `cooldown_distance`, `gust_speed`, `rocking_torque_per_sail`, `gust_period_seconds`, `fade_distance`, `storm_chance_multiplier`.
- `[wind.turbulence].storm_direction_multiplier` — ускорение случайных поворотов при грозе, по умолчанию 3: интервал сокращается втрое. Фаза продолжается непрерывно, без скачка при смене погоды. Часы случайных поворотов общие для мира: ускорение определяется наиболее сильной грозой SC в наблюдаемых областях активных аппаратов. Это сохраняет единый зональный рисунок; пространственная погода по-прежнему отдельно задаёт местную скорость и облачное направление.

Для проверки: `/aeroworks wind` показывает ветер по трём осям, число парусов, количество соседних горных потоков, остаток пути турбулентности и исходный вращающий момент для ближайшего аппарата в радиусе 128 блоков. Команда только читает состояние. Количество соседних потоков не означает попадание внутрь столба: фактическое воздействие видно по вертикальной скорости Y. Режим `wind.field.dynamic=false` сохраняет прежний постоянный горизонтальный ветер без новых эффектов.

Автоматические проверки `testFlightWind`: границы и плавность столбов, оба знака вертикального ветра, ограничение перекрытия, ограниченные независимые порывы, масштаб момента по числу парусов, жизненный цикл по расстоянию, независимость вероятности от дробления шага и ускорение поворотов в грозу. Полётный баланс и ощущения покачивания требуют проверки в игре.


### Быстрая смена момента, тряска камеры и индикаторы подъёма

Вращающий момент турбулентности теперь **обязательно меняет знак** каждый `wind.turbulence.rocking_period_seconds` (по умолчанию 0.16 с, полный цикл 0.32 с). Три оси сдвинуты по фазе, сила каждого импульса случайная. В точках смены знака момент плавно проходит через ноль; соседние случайные значения больше не могут долго вращать аппарат в одну сторону. Ветровые порывы сохраняют свой отдельный `gust_period_seconds`. Число парусов, давление и коэффициент давления продолжают масштабировать общий момент один раз на аппарат за физический подшаг.

Сервер отправляет визуальное состояние игрокам 4 раза/сек. Камера трясётся только у стоящего/сидящего на турбулентном аппарате игрока: используется `Sable.HELPER.getTrackingOrVehicleSubLevel`, идентификатор аппарата проверяется и на клиенте. Пролёт рядом с самолётом не запускает тряску. Отклонения ограничены примерно 1° крена, 0.45° тангажа и 0.25° рыскания при стандартной силе; они добавляются к отрисовке камеры, не изменяют прицел/поворот сущности и не накапливаются. Огибающая эпизода плавная. Выход с аппарата, смена мира и устаревание данных прекращают эффект.

Восходящие горные потоки получают белые облачные шапки около середины высоты столба. Шапки следуют текущему центру и высоте реального потока; нисходящие потоки не помечаются. Они состоят из редких крупных частиц с плавным появлением/исчезновением и небольшим подъёмом, используют штатную глубину и проход частиц. На один клиент передаётся до 8 ближайших маркеров в радиусе 384 блоков, до 512 байт в пакете. На поиск гор действует прежний общий лимит 32 проверок точек за тик; чанки принудительно не загружаются. Поиск рядом с игроками позволяет увидеть поток до попадания самолёта в него. При первом обнаружении требуется прогрев кэша и плавное проявление потока. Маркер декоративный: не меняет плотность Simple Clouds, туман или физику.

Отдельный клиентский конфиг `config/aste_aeroworks-wind-client.toml`:

```toml
camera_shake = true
camera_shake_strength = 1.0
updraft_clouds = true
# Общий бюджет новых частиц на все облачные индикаторы, не на каждый поток.
indicator_particles_per_second = 32
```

На настройке частиц «минимум» индикаторы не рисуются; на «уменьшено» бюджет вдвое ниже. Серверная физика от этих настроек не меняется. Новый общий параметр `rocking_period_seconds` добавляется в существующий common-конфиг автоматически.

Проверки дополнены обязательной сменой знака при разных seed, непрерывностью импульсов, проверкой покачивания на 20 Гц, ограничением и отсутствием накопления углов камеры, roundtrip сетевого пакета, ограничением его размера/числа маркеров и отбрасыванием нечисловых координат. Визуальный вид облачных шапок и интенсивность тряски требуют проверки в игровом клиенте.

### Высотная эффективность винтов

Винты Aeronautics теперь теряют тягу с высотой быстрее, чем крылья теряют подъёмную силу. Штатный `BlockEntityPropeller.getScaledThrust` уже умножает тягу на давление; к этому давлению только для выбранных винтов добавляется коэффициент:

`efficiency = exp(-((Y - fade_start_height) / scale_height)^2)` выше начала перехода, иначе `1`.

Переход начинается с нулевой производной и не вводит жёсткого потолка высоты. В common-конфиг автоматически добавляется:

```toml
[propellers]
altitude_efficiency_enabled = true
fade_start_height = 128.0
scale_height = 256.0
```

`fade_start_height` — абсолютная мировая Y; до неё сохраняется прежняя зависимость винтов от общего давления. `scale_height` — подъём после начала перехода, на котором дополнительная эффективность равна `1/e`; уменьшение этого параметра ускоряет ослабление тяги. Модель работает в измерениях из включённой секции `atmosphere`. Отключение `propellers.altitude_efficiency_enabled` убирает только дополнительный штраф винтов.

При стандартной атмосфере и одинаковых исходных RPM/винте/скоростном множителе:

| Мировая Y | Плотность для крыльев | Итоговый множитель тяги винта |
|---|---:|---:|
| 128 | 93.94% | 93.94% |
| 250 | 83.39% | 66.45% |
| 400 | 72.03% | 23.29% |
| 600 | 59.25% | 1.98% |

Множители считаются относительно исходной номинальной тяги и базового давления измерения. Тяга винта также сохраняет штатную зависимость Sable от набегающего воздуха. Результат не задаёт гарантированную максимальную высоту: она зависит от массы, запаса тяги, площади крыла и восходящих потоков. Сильный поток или инерция всё ещё могут поднять винтовой самолёт выше высоты устойчивого моторного полёта.

Обрабатываются только блоки тега `aste_aeroworks:altitude_sensitive_propellers`: по умолчанию деревянный, андезитовый и умный винты, обычный и гироскопический подшипники винта Aeronautics. Тег можно расширить датапаком для других настоящих винтов, использующих тот же API. Реактивные/ракетные двигатели не включены в тег; само использование ими общего API тяги Sable не включает дополнительный штраф. Крылья, сопротивление и воздушные потоки сохраняют текущие формулы.

Точка внедрения — единственный вызов `DimensionPhysicsData.getAirPressure` внутри стандартного `BlockEntityPropeller.getCurrentAirPressure`. Sable уже переводит координаты винта из служебного участка конструкции в мировые до этого вызова: повторных преобразований позиции, новых векторов, поиска блоков/чанков, шума и циклов по парусам нет. Проверка тега использует сохранённое состояние самой block entity. Базовое давление, ноль в вакууме и штатный `getAirflowScaling` сохраняются.

Проверены настоящий байткод Sable 2.0.6 и официальный код Aeronautics: [BasePropellerBlockEntity](https://github.com/Creators-of-Aeronautics/Simulated-Project/blob/3705df2062bebba42c3ab3d6b3dd09faa1512850/aeronautics/common/src/main/java/dev/eriksonn/aeronautics/content/blocks/propeller/small/BasePropellerBlockEntity.java) и [PropellerBearingBlockEntity](https://github.com/Creators-of-Aeronautics/Simulated-Project/blob/3705df2062bebba42c3ab3d6b3dd09faa1512850/aeronautics/common/src/main/java/dev/eriksonn/aeronautics/content/blocks/propeller/bearing/propeller_bearing/PropellerBearingBlockEntity.java) используют стандартный интерфейс винта. `testPropellerProfile` проверяет сохранение низких высот, плавность, монотонность, разницу с крыльями, настройки и предельные значения. Проверка контрактов подтверждает мировую позицию, однократную выборку давления, область тега и отсутствие дополнительных чтений мира. Полётный баланс требует проверки в игре.

### Случайные механические отказы и ремонт ключом

Первый тип блока в списке отказов — `aeronautics:propeller_bearing`. Новые отказы возможны только на физической конструкции Sable, на которой находится живой игрок не в режиме наблюдателя. Отказавший подшипник перестаёт давать тягу, а его эффективное вращение Create становится нулевым. Крупный винт может ещё некоторое время вращаться по штатной инерции Aeronautics, но тяга обнуляется сразу. Сохранённые RPM, источник и идентификатор кинетической сети не стираются: блок восстанавливает работу после ремонта без пересборки сети. Крылья и общая аэродинамика не изменены.

Наземные механизмы и конструкции без игрока не участвуют в розыгрыше отказов. Работа выбранных блоков учитывается только на сервере каждый игровой тик; временной розыгрыш проводится после секунды накопленного вращения, а стартовый — при начале движения. В розыгрыше участвуют только блоки из списка с ненулевым эффективным `getSpeed()` Create: знак вращения не важен, входящая и исходящая кинетика обрабатываются одинаково. Остановленные/перегруженные механизмы с нулевым вращением не отказывают. Выгруженные чанки и время вне игры не накапливают отказы.

В common-конфиг добавляется секция:

```toml
[failures]
enabled = true
blocks = ["aeronautics:propeller_bearing"]
# Высокий ТЕСТОВЫЙ риск: 30% за минуту работы при 64 RPM, без полёта и ниже Y128.
base_chance_per_minute = 0.3
reference_rpm = 64.0
rpm_risk_weight = 1.0
reference_flight_speed = 40.0
flight_speed_risk_weight = 1.0
altitude_start = 128.0
altitude_scale = 256.0
altitude_risk_weight = 1.0
turbulence_multiplier = 8.0
maximum_risk_multiplier = 256.0
repair_grace_seconds = 15
```

Риск учитывает и RPM самого блока, и модуль мировой скорости аппарата. При стандартных весах множители равны `max(0.05, abs(RPM)/64)`, `1 + speed/40`, `1 + max(0, Y-128)/256`. Во время эпизода турбулентности именно этого аппарата произведение дополнительно умножается на 8 и ограничивается `maximum_risk_multiplier`. Множитель усиливает **интенсивность отказов**, а не линейно складывает проценты. Вероятность за интервал `dt` равна `1 - (1-base_chance_per_minute)^(dt * risk_multiplier / 60)`, поэтому число физических подшагов не меняет шанс.

Например, при 128 RPM, 40 блоках/с и Y300 шанс около **3.90% за секунду**, в турбулентности — **27.24% за секунду**. При 64 RPM на неподвижной конструкции с игроком и ниже Y128 — около 0.59% за секунду. Эти значения специально высокие для тестирования; уменьшение общего `base_chance_per_minute` снижает временной риск всех типов блоков, а индивидуального `base_chance_per_minute_factor` — только выбранного типа. Общий ноль отключает временной канал у всех блоков, а общий `chance_per_start=0` — стартовый; `enabled=false` также временно убирает последствия уже сохранённых отказов. Возврат `enabled=true` снова применяет их, пока блок не отремонтирован. Удаление типа из списка прекращает новые отказы этого типа, но не стирает уже произошедший отказ.

Починка: нажмите по отказавшему блоку ключом Create, инструментом из `c:tools/wrench` или `create:wrench`. Действие потребляется до обычного поворота/снятия блока ключом. Ремонт бесплатный, инструмент не расходуется; неподвижный исправный блок не получает защиту от простого нажатия ключом. После ремонта действует примерно 15 секунд защиты от повторного отказа (загруженное игровое время), чтобы тестовый риск не ломал блок сразу повторно. В очках инженера показывается красное сообщение об отказе и подсказка о ключе; успешный ремонт подтверждается сообщением и звуком. Решение принимает сервер, с обычными проверками возможности взаимодействия игрока.

Состояние отказа и оставшаяся защита сохраняются в NBT block entity и синхронизируются обычными пакетами Create. Они сохраняются при перезагрузке и копировании данных сборки/разборки конструкции, включая ранний выход Create из `read` после перемещения. Здоровые блоки без защиты не добавляют вложенный NBT-тег. В физическом расчёте выполняется лишь чтение флага, без случайных чисел, поиска блоков, чанков или погоды. Высота вычисляется из мировой позы Sable, скорость читается из его готового `latestLinearVelocity`, турбулентность — из уже опубликованного снимка ветра. Проверка не запрашивает native physics handle и не рассчитывает облачный шум.

Список рассчитан на кинетические block entity Create. Первым проверяемым механизмом является подшипник винта Aeronautics; специальные блоки других модов могут потребовать отдельного адаптера остановки функции. Проверки включают работу/простой, абсолютные RPM, высоту, скорость, множитель турбулентности, независимость вероятности от разбиения времени, независимые отказы блоков, ремонт/защиту, сохранение и синхронизацию NBT. CI сверяет реальные сигнатуры Create 6.0.10 и Sable 2.0.6. Игровые клики ключом, визуальное торможение винта и баланс требуют проверки в сборке пользователя.


### Дым поломки и защита автоматических механизмов

Новый отказ разрешён только если **именно на этой физической конструкции находится игрок**. Используется связь Sable `getTrackingOrVehicleSubLevel`: стоящий на палубе игрок или сидящий в кресле подходит, соседний самолёт и просто близкий игрок не подходят. Для сна учитывается кровать внутри конструкции. Наблюдатели и мёртвые игроки не включают риск. Присутствие проверяется по UUID тела до расчёта вероятности и получения случайного числа. Наземные механизмы и беспилотные конструкции новых отказов не получают. Список занятых тел обновляется не чаще одного раза за серверный тик на измерение и разделяется всеми проверяемыми деталями; очищается при выгрузке мира/остановке сервера. Кэш не удерживает выгруженные миры.

Уже случившийся отказ не исчезает при выходе игрока: деталь сохраняет неисправность до починки ключом. Возвращение на ранее оставленную исправную конструкцию возобновляет обычный риск; время без игрока не накапливается.

При новом отказе из мировой позиции детали однократно слышится металлический скрежет с треском: сочетание пониженного звука повреждения железного голема и сломанного щита. Сервер рассылает обычные звуковые события ближайшим игрокам, громкость регулируется категорией «Блоки». Продолжающийся отказ, загрузка сохранённой поломки и синхронизация NBT не запускают звук повторно.

От неисправной детали поднимается небольшой шлейф стандартного серого дыма. Эмиттер переводится из координат блока в текущую визуальную мировую позу конструкции Sable, поэтому дым выходит из самой детали на летящем/повёрнутом аппарате. Уже выпущенный дым остаётся в мировом пространстве и рассеивается. Нужен только существующий флаг поломки из синхронизации Create: дополнительных сетевых пакетов частиц нет. После ремонта новые порции дыма сразу прекращаются, оставшиеся частицы естественно исчезают.

Дым создаётся только клиентом, примерно 2.5 частицы/сек на деталь при обычных настройках частиц, в пределах 96 блоков от камеры. Общий предел — 2 новых частицы за клиентский тик (40/сек). На «уменьшено» частота вдвое ниже, на «минимум» дым отключён. Фаза эмиссии меняется между окнами, чтобы одни и те же детали не всегда занимали бюджет первыми. Нет дополнительных проходов рендеринга, загрузки чанков или удержания клиентского мира статическим кэшем.


### Индивидуальные профили блоков и короткие движения закрылков

В `[failures].block_profiles` автоматически появляется отдельная строка для каждого ID из `[failures].blocks`. При загрузке или перезагрузке настроек отсутствующие строки дописываются в существующий common-конфиг; пользовательские коэффициенты не заменяются. Старые абсолютные параметры однократно переводятся в коэффициенты. Повторная загрузка не создаёт дубликатов. При добавлении нового блока достаточно добавить его в `blocks`, затем загрузить/перезагрузить конфиг, и отредактировать сгенерированный профиль.

```toml
[failures]
base_chance_per_minute = 0.3
chance_per_start = 0.02
blocks = ["aeronautics:propeller_bearing", "create:mechanical_bearing"]
block_profiles = [
    "aeronautics:propeller_bearing; base_chance_per_minute_factor=1.0; chance_per_start_factor=0.0",
    "create:mechanical_bearing; base_chance_per_minute_factor=1.0; chance_per_start_factor=1.0; rpm_risk_weight_factor=0.0"
]
```

Вращатель `create:mechanical_bearing` по умолчанию получает базовый шанс 2% **на начало движения** и отсутствие ослабления этого шанса из-за малых RPM. Скорость самолёта, высота и турбулентность по-прежнему усиливают риск: 2% не являются итоговым шансом в любой обстановке. Для винтового подшипника отдельного стартового риска по умолчанию нет, сохраняется риск за время вращения. Предустановка вращателя применяется только при создании новой строки; вручную заданные значения не перезаписываются. Сам вращатель в `blocks` автоматически не добавляется.

Каждая строка начинается с ID блока, параметры разделяются точкой с запятой. Все числовые настройки профиля — **множители общих значений**, с суффиксом `_factor`. Неуказанный множитель равен 1. Например, при общем `base_chance_per_minute=0.1` фактор `2` даёт блоку базовый шанс 0.2 за минуту; после изменения общего шанса на 0.01 тот же профиль даёт 0.02. Общий ноль нельзя обойти индивидуальным множителем.

- `base_chance_per_minute_factor` — множитель общего шанса за минуту фактического вращения.
- `chance_per_start_factor` — множитель общего `chance_per_start` на начало движения/реверс. Для новых профилей винтового подшипника он равен 0, для механического вращателя — 1.
- `reference_rpm_factor`, `rpm_risk_weight_factor`, `reference_flight_speed_factor`, `flight_speed_risk_weight_factor`, `altitude_start_factor`, `altitude_scale_factor`, `altitude_risk_weight_factor`, `turbulence_multiplier_factor`, `maximum_risk_multiplier_factor` — множители соответствующих общих параметров.
- `repair_grace_seconds_factor` — множитель общей защиты после ремонта.
- `count_reversals_as_start=true/false` — переключатель учёта реверса, по умолчанию true. Он не является числовым множителем.

Коэффициенты должны быть конечными и неотрицательными; эталонные RPM/скорость и масштаб высоты после умножения должны оставаться положительными. Базовые шансы ограничиваются 100%, защита — 3600 секундами; множитель турбулентности и потолок риска не опускаются ниже 1. Нулевой вес RPM/высоты/скорости отключает влияние данного фактора нагрузки, а не весь риск.

Старые абсолютные параметры автоматически заменяются на коэффициенты относительно **исходных стандартных значений** мода: например, старый шанс 0.3 превращается в фактор 1, а 0.6 — в фактор 2. Поэтому уже изменённые общие настройки начинают действовать сразу после обновления; старое сгенерированное значение больше не маскирует общий шанс. Старый стартовый шанс делится на исходные 0.02, защита — на 15 секунд. Отсутствующий в старой строке стартовый шанс сохраняется как фактор 0. Конвертированные строки сохраняются в common-конфиг, миграция повторно не применяется и не создаёт циклов сохранения.

Шанс начала движения и шанс за время независимы и объединяются через вероятность выживания; оба усиливаются нагрузкой, высотой и турбулентностью. При стартовом событии используется текущий RPM, а для накопленного времени — средний абсолютный RPM за это время. Разбор коэффициентов и пересчёт эффективных профилей выполняются только при загрузке/перезагрузке конфига.

Короткие движения больше не пропускаются секундной выборкой: выбранные механизмы получают лёгкий учёт активности каждый игровой тик. Тики вращения суммируются между короткими движениями, а обычный розыгрыш по времени выполняется после накопления секунды действительной работы, только на работающем блоке. Стартовый шанс проверяется немедленно при наблюдаемом начале/смене направления. Изначальное наблюдение уже вращающегося блока после загрузки, изменение настроек и посадка игрока на уже работающую конструкцию не создают искусственного стартового события. Проверка присутствия игрока выполняется до накопления активности; работа без игрока и время защиты после ремонта не учитываются. Перенос в другое физическое тело очищает накопленную долю времени.

Профили разбираются только при загрузке/перезагрузке конфига и кэшируются по типу блока. У механизмов вне списка не запрашиваются RPM или данные Sable. Нет разбора строк, облачного шума, поиска чанков или случайных бросков на каждом физическом подшаге. Ремонт, дым, сохранение отказов и защита беспилотных/наземных механизмов сохраняются.

Некорректная строка, неизвестный ключ или недопустимое число выдаёт предупреждение и сохраняет прежние безопасные параметры для этого ID; корректные профили остальных блоков продолжают применяться. Тесты проверяют независимые профили, наследование/валидацию, автоматическое дополнение без перезаписи и циклов сохранения, суммирование коротких движений, старты/реверсы, отсутствие ложного старта при загрузке/посадке и защиту времени без игрока.

### Частицы отрыва потока

При превышении `attached_flow_angle_degrees` (по умолчанию 30°) у активных аэродинамических поверхностей появляются короткие белые завихрения. Учитываются местный поток, ветер, вращение, вложенная поза и давление атмосферы; на местной скорости меньше `stall_particle_min_speed` (10 м/с по умолчанию) эффект отсутствует. Полное прежнее сопротивление теперь возвращается на 45°, между 30° и 45° — плавный переход. Эффект выключается через `aerodynamics.stall_particles=false`, не влияет на силы и не обозначает отдельную турбулентность аппарата. Применяются стандартная глубина и настройки частиц Minecraft.

Ограничения: не более 3 новых частиц на аппарат каждые 5 игровых тиков, очередь максимум 96 образцов и максимум 16 отправок за серверный тик на все аппараты. Сбор образцов происходит в уже существующем расчёте поверхностей; отправка — только в серверном потоке. Старые образцы отбрасываются.

Старая стандартная пара углов 12°/25° автоматически заменяется на 30°/45° при загрузке конфига и сохраняется. Иные пользовательские пары остаются прежними.

### Падение lift при сваливании

Собственная подъёмная сила (`liftScalar > 0`, односторонние паруса) до `attached_flow_angle_degrees` сохраняется. Затем за `stall_lift_transition_degrees` (5°) smoothstep от абсолютного синуса угла снижает её до `stalled_lift_fraction` (0.1). По умолчанию: 30° — начало, 35° — 10% прежней lift при том же угле и скорости. Значение 1 отключает дополнительное падение. При выравнивании относительно местного потока lift восстанавливается по той же кривой. Оба soft cap Lift Patch по-прежнему действуют. Нормальное давление и двухсторонние рули остаются прежними; потеря intrinsic lift не устраняет автоматически обратное рыскание.

Частицы имеют отдельный порог `aerodynamics.stall_particle_min_speed = 10.0` м/с. Это местная скорость относительно воздуха в точке поверхности с учётом вращения и ветра. Порог ограничивает только визуализацию, не физику сваливания.
