# Aero Works

Minecraft 1.21.1 / NeoForge 21.1.256. Клиентский туман внутри облаков Simple Clouds 0.7.3+1.21.1.

Туман учитывает позицию **камеры**, высоту облаков, тип и границы региона, слои шума, движение ветра и анимацию градиентов. Плотность рассчитывается на CPU по формуле `cube_mesh.comp` и MIT-алгоритму psrdnoise из приложенного JAR. Просветы и промежутки между слоями остаются прозрачными; режим AMBIENT, который убирает облака вокруг камеры, не создаёт туман. Чтения данных с GPU нет.

Обычная геометрия использует штатные цвет и сферические дистанции Minecraft fog через `ViewportEvent`, которые читает и Sodium. Дальность зависит от плотности: `visibility / strength`, с сохранением более короткого штатного тумана.

Дополнительный depth-aware проход выполняется после возврата `LevelRenderer.renderLevel`, когда уже завершена обычная местность, Sable, DH и дополнительные слои. Вызовы частиц и `renderSnowAndRain` откладываются до завершения этого прохода. Их камера, матрицы и параметры штатного fog сохраняются в момент исходного вызова, затем эффекты рисуются на итоговой сцене. Это позволяет охватить туманом все чанки и сохранить дождь/снег перед облаками. Порядок solid/translucent частиц и погоды сохраняется; эффекты рисуются один раз. Проекции Minecraft и DH хранятся отдельно.

Для DH откладывается штатный composite облаков до этого заключительного прохода. Непрозрачный цвет облаков и weighted transparency смешиваются с готовым изображением только перед ближней геометрией; сравниваются восстановленные расстояния из разных проекций. Это исправление направлено на дефект Sodium 0.8.x, при котором поздние чанки перекрывают ранее нарисованные облака. Экранный туман остаётся для DH и остальных рендереров, обходящих Minecraft fog. DH не становится обязательной зависимостью. Совместимость с Sodium 0.8.13 и Sodium Extra 0.9.3 пока требует проверки в игре.

Финальное копирование использует собственный `cloud_fog_copy` с заменой цвета (`ONE, ZERO`), а результат fog-pass имеет alpha=1. Альфа исходного main target не означает видимость сцены: небо и DH могут содержать корректный RGB при alpha=0. Ванильный `blit` со смешиванием `SRC_ALPHA` в очищенный main target стирал такие части изображения. Тесты проверяют оба прохода, включая нулевую и частичную альфу исходной сцены, вне облака и внутри него.

В воде, лаве и рыхлом снегу используются штатные эффекты. Эффект не увеличивает видимость уже затуманенной сцены. Обработчики и миксины загружаются только на клиенте. Состояние и ресурсы сбрасываются при выходе, смене мира и перезагрузке ресурсов; framebuffer и проекция восстанавливаются перед отрисовкой руки.

## Настройки

После первого запуска: `config/aste_aeroworks-client.toml`.

```toml
[cloud_fog]
enabled = true
# Дальность полной непрозрачности в плотном облаке, в блоках.
visibility = 24.0
# Ширина перехода по значению плотности шума.
boundary_width = 0.15
# Положительное значение включает туман раньше, в разреженной кромке облака.
density_offset = 0.0
# Время сглаживания в тиках, 0 отключает сглаживание.
transition_ticks = 3.0
# Раннее появление на внешней кромке без изменения полной плотности.
edge_density_margin = 0.15
# Серый цвет: яркость на кромке и внутри, относительно освещения облаков.
edge_fog_brightness = 0.9
dense_fog_brightness = 0.65
```

Для более раннего и быстрого срабатывания попробуйте `density_offset = 0.1`, `boundary_width = 0.05`, `transition_ticks = 1.0`. Для более густого тумана уменьшите `visibility`, например до 16. Теперь слабая плотность меняет прозрачность итогового тумана, а не смешивает дальность 24 блока с многокилометровой дальностью прорисовки.

При смене мира и дальних телепортациях состояние сбрасывается. Внутри закрытого самолёта/помещения эффект тоже работает: проверяется облако в позиции камеры, герметичность кабины пока не моделируется.

## Сборка и зависимости

`./gradlew build` (Windows: `gradlew.bat build`), JDK 21. Сборка использует JAR Simple Clouds из `libs`, API 1.4-1.21.1 и CrackersLib 1.21.1-0.4.6 из Maven автора. Для запуска клиента разработки Simple Clouds и CrackersLib подключены через `localRuntime`; API поставляется внутри Simple Clouds. При обычной установке установите Simple Clouds и CrackersLib отдельно — Aero Works не включает их в свой JAR.

Create лежит в `libs`; API Sable подключён для серверного ветра. Сборка нацелена на NeoForge 21.1.256, как основная сборка пользователя.

`check` запускает 15 проверок периодичности шума, границ/пустот/слоёв облака, ветра, плавности при разном FPS и чувствительности, ранней кромки, серого цвета и порядка отложенных эффектов. CI также запускает `python3 scripts/test_cloud_fog_shader.py`: 28 проверок фактического fragment shader на программном OpenGL (Mesa/EGL), включая обычную геометрию, разные проекции Minecraft/DH и прозрачность при слабом облаке. Проверки не заменяют запуск полной сборки Minecraft.

## Проверка в игре

1. Полёт в плотное облако: дальность уменьшается примерно до 24 блоков, цвет соответствует облаку.
2. Выход из облака, полёт через просвет и выше/ниже слоёв: видимость восстанавливается.
3. Проверить движущееся облако, DEFAULT и SINGLE, вид от третьего лица, день/ночь и грозу.
4. Проверить воду/лаву, слепоту, смену измерения, отключение `cloud_fog.enabled` и `renderClouds` Simple Clouds.

Алгоритм совпадает с непрерывным полем шума Simple Clouds, но сам мод рисует облако кубическими ячейками и обновляет mesh с задержкой. Поэтому на поверхности возможна погрешность в несколько блоков; она смягчается переходом. Сторонние шейдерпаки и комбинация версий Sodium/Sable/Distant Horizons требуют проверки в игре: здесь протестирован shader, а полный игровой клиент не запускался.

## Идентификатор мода

ID Aero Works — `aste_aeroworks`. Имя JAR после сборки: `aste_aeroworks-1.0.0.jar`. Старый `aeroworks-1.0.0.jar` нужно убрать из папки `mods` перед установкой нового. ID `aeroworks` принадлежит другому моду, который могут требовать Gadgets ’n Gizmos и Create Thrusters; Aero Works не заменяет эту зависимость. Если ранее менялись параметры нашего тумана, перенесите их из `aeroworks-client.toml` в `aste_aeroworks-client.toml`.

Новые настройки `edge_density_margin`, `edge_fog_brightness`, `dense_fog_brightness` автоматически добавляются и в существующий конфиг. Расширенная кромка начинается раньше, но достигает полной силы в той же точке плотности, что и раньше; `visibility` и верхняя граница силы остаются прежними. Цвет обоих путей рендеринга одинаков: яркость облаков переводится в серый и умножается на плавный коэффициент от 0.9 до 0.65 по силе тумана.

При выборе расстояния тумана пиксель обычной поверхности имеет приоритет над смешанным буфером DH/облаков. DH используется для пикселей без обычной поверхности, а реально нарисованное непрозрачное облако перед поверхностью может перекрыть её. Скрытая LOD-геометрия не должна менять туман поверх обычного чанка. Три дополнительные OpenGL-проверки сравнивают туман земли при изменении глубины скрытого LOD и сохраняют туман на видимом LOD без обычных чанков.

Туман применяется отдельно к фону и слоям облаков. Глубина близкой грани облака больше не используется как расстояние до неба за ней. При полной силе тумана внутренние непрозрачные/прозрачные грани облачного mesh переходят в серый цвет; видимость близкой земли не меняется. Прозрачные облака учитываются и над небом с пустым depth buffer. Шесть новых OpenGL-проверок покрывают эти слои и отрисовку передних осадков/частиц после тумана.

CI проверяет новую точку внедрения по реальному байткоду `LevelRenderer` из mapped JAR NeoForge, включая дополнительные аргументы Frustum и Predicate у ParticleEngine.render. Это проверка исполняемого места вызова, а не только компиляции Java.

Очередь эффектов очищается в начале кадра и при сбросе ресурсов. Повторный вызов завершения кадра не рисует туман или эффекты второй раз. Проверки Java включают позднюю геометрию между исходными вызовами частиц, сохранение порядка эффектов, обход очереди, незавершённый кадр и ошибку fog-pass. CI сверяет точки перенаправления ParticleEngine.render и renderSnowAndRain с mapped NeoForge 21.1.256. Полный игровой клиент с Sodium/Sable/DH здесь не запускался.

## Базовый физический ветер

Sable **2.0.6**; учтён **Create Aeronautics Lift Patch 1.1.0** (его внутренний modId `ldfix`, версия в metadata — `1.0.0`). Конфиг: `config/aste_aeroworks-common.toml`:

```toml
[wind]
enabled = true
velocity_x = 8.0
velocity_y = 0.0
velocity_z = 0.0
# Множитель подъёмной силы и сопротивления парусов/крыльев.
sail_pressure_coefficient = 1.0
```

Скорости в блоках/сек, в мировых осях: +X восток, +Y вверх, +Z юг. По умолчанию используется погодное поле: поверхностный ветер около 2–3 блоков/с в ясную погоду, высотный около 8, с усилением в дождь и грозу. Прежний постоянный ветер включается через `[wind.field].dynamic=false`; тогда работают `velocity_x/z`. Вертикального ветра в этой версии нет, `velocity_y` сохранён для чтения старых конфигов и игнорируется. Атмосферное давление и отсутствие атмосферы по-прежнему учитывает Sable. Нужны серверная установка мода и паруса Create либо другие блоки с API `BlockSubLevelLiftProvider`. Голые корпуса не получают дополнительную силу. Это физический ветер; облака и частицы пока не меняют своё движение.

Перед каждым вызовом аэродинамики подставляется `v_body - v_wind`. Вращательное движение точки паруса остаётся штатным: `v_body + omega × r - v_wind`. Меняется только аргумент скорости в двух местах `ServerSubLevel.prePhysicsTick`: поверхности самой физической конструкции и вложенных Create-контрапций, в том числе подшипников. Общая скорость тела не изменяется: плавучесть, остальные блоки и следующие паруса получают исходные данные.

Lift Patch полностью заменяет метод подъёмной силы и сопротивления. Aero Works не заменяет этот метод и не добавляет вторую силу: относительная скорость поступает в существующие формулы патча, сохраняя коэффициенты, квадратичную зависимость, ограничения, плечо силы и группировку. При нулевом ветре или `enabled=false` передаётся исходная скорость. Без Lift Patch тот же вход обрабатывает стандартная аэродинамика Sable.

`WindFields.sample(WindSample, Vector3d)` — отдельная точка выборки поля ветра. `WindSample` содержит уровень, мировую позицию физического тела (`logicalPose.position`), время в секундах и runtime id для выбора подготовленного сервером погодного снимка. Старый конструктор без id сохранён; он использует ясную погоду, пока идентичность тела неизвестна. Поле выбирается один раз за физический шаг тела; все его поверхности, включая вложенные контрапции, используют общий поток. `WindFields.setProvider(WindField)` позволяет позже заменить постоянное поле функцией высоты, биома, облаков или областей мира, не меняя интеграцию с физикой. Это приближение для пространственно неоднородного ветра: большая конструкция пока получает поток в одной опорной точке. При развитии поля можно добавить ограниченное число пространственных групп, не возвращая запрос на каждый парус. Провайдер вызывается из физического расчёта, должен быть потокобезопасным, не изменять мир и использовать подготовленные снимки для данных, недоступных на физическом потоке. Неполные векторы обнуляются перед выборкой, NaN/Infinity отбрасываются.

При сборке compile classpath получает Sable и его вложенные API-библиотеки из JAR; они не упаковываются в Aero Works. Sable и Lift Patch добавлены в localRuntime разработки. Для теста с Create установите Create и его зависимости в dev-сборку. `testWind` запускает 12 проверок кинематики/провайдера, включая общий поток, встречный ветер, боковой/вертикальный поток, неизменность скоростей, вращение и мировые координаты вложенных парусов. CI сверяет обе точки вызова и сигнатуру метода Lift Patch по байткоду. Полный запуск Minecraft и физика парусов в игре ещё требуют проверки.

Проверка в игре: соберите свободную физическую платформу с вертикальным парусом, обращённым поперёк оси X; сравните `velocity_x=8`, `-8`, `0`. Разнесённые паруса могут давать момент и поворачивать конструкцию. Затем проверьте повёрнутое крыло и парус на вложенном подшипнике. Итоговое ускорение зависит от массы, площади, ориентации, давления и настроек Lift Patch.

## Оптимизация ветра и тумана

Вместо `ModifyArgs` с обёрткой и несколькими новыми векторами на каждом парусе используются типизированное перенаправление и два переиспользуемых вектора на физическое тело. Один запрос поля и одно вычитание скорости на шаг; в цикле поверхностей нет новых объектов Aero Works. Кэш сбрасывается на каждом `prePhysicsTick`, а не игровом тике. Контрапции без аэродинамических поверхностей не запрашивают ветер. Тест с 20 000 обращений за два шага проверяет ровно две выборки и общий объект скорости. Sable по-прежнему считает подъёмную силу/сопротивление каждой поверхности: его группировка предназначена для отображения сил. Формулы и моменты Lift Patch сохраняются.

Плотность тумана проверяется адаптивно: первая выборка немедленная, затем 0.5–5 раз/с. Резкое изменение сырой плотности (>=0.1) или видимой силы (>=0.2) назначает следующую проверку через 0.2 с. Почти неизменная плотность увеличивает интервал вдвое до 2 с. После подтверждения полного тумана интервал не короче 1 с, даже если шум внутри него заметно меняется. Обычное движение не обходит ограничение частоты. Смена мира, телепортация дальше 128 блоков и откат времени сбрасывают расписание. Вход в диапазон возможных высот также вызывает немедленную выборку. На стабильной сцене при 120 FPS за десять секунд тест выполняет не более шести выборок вместо прежних 200.

До поиска региона камера сравнивается с объединённым диапазоном высот всех доступных типов облаков. Диапазон берётся из metadata слоёв и включает отрицательные смещения относительно базовой высоты; кэш обновляется раз в игровую секунду. Ниже нижней и выше верхней границы не выполняются ни поиск региона, ни упаковка, ни шум. Пустой индекс типов при синхронизации консервативно отключает отсечение. Сглаживание, цвет и штатный fog обновляются каждый кадр. Упакованные слои переиспользуются и обновляются раз в игровую секунду для правок на месте. Выход из мира и перезагрузка ресурсов сбрасывают кэши. Цена редких проверок — обнаружение новой границы может задержаться до 2 с на ранее стабильном участке; после первого изменения частота автоматически растёт. Это число вычислений, не измерение FPS.

Отложенные эффекты делят один снимок восстанавливаемого состояния OpenGL на всю очередь. Исходные эффекты больше не читают неиспользуемые framebuffer/viewport. При трёх эффектах это сокращает чтения состояния драйвера в `DeferredEffectState` с 72 до 39 на кадр; порядок, матрицы и восстановление состояния остаются прежними. Инверсия проекции переиспользует матрицу. Shader пропускает прозрачные буферы для пикселей, полностью закрытых плотным туманом. Полноэкранные проходы сохранены для корректной геометрии DH, неба и облаков; их стоимость не устранена. Реальные FPS и фризы нужно сравнить на той же сцене в полной сборке.


`[wind].sail_pressure_coefficient` в `config/aste_aeroworks-common.toml` задаёт множитель аэродинамического давления: `1.0` сохраняет прежнюю силу, `0.1` уменьшает её в десять раз, `0.0` отключает аэродинамическую силу парусов/крыльев. Диапазон 0–10, значение по умолчанию 1. Коэффициент линейно масштабирует импульсы и моменты подъёмной силы и сопротивления, включая движение конструкции в неподвижном воздухе; скорость ветра и общая физическая длительность шага не меняются. Это эквивалент множителя давления в формулах Sable 2.0.6 и Lift Patch 1.1.0: только аргумент интегрирования аэродинамики умножается на коэффициент, прочие силы и контроллеры получают исходный шаг. Конфиг читается один раз на тело за шаг; повторных запросов поля, векторов или второго расчёта аэродинамики на парус не добавлено.


## Настраиваемая атмосфера Sable и Lift Patch

В `config/aste_aeroworks-common.toml` добавлена секция:

```toml
[atmosphere]
enabled = true
dimensions = ["minecraft:overworld"]
reference_height = 64.0
scale_height = 1024.0
fade_start_height = 3072.0
ceiling_height = 4096.0
```

`reference_height` — абсолютная мировая высота Y, на которой относительная плотность равна 1. `scale_height` — подъём, уменьшающий её в e раз. До начала финального перехода используется `density = min(1.5, exp((reference_height - Y) / scale_height))`. Начиная с `fade_start_height` эта плотность дополнительно умножается на `1 - smoothstep(fade_start_height, ceiling_height, Y)`; на `ceiling_height` и выше — точный ноль. Плотность непрерывна; первая производная совпадает в начале финального перехода и обращается в ноль у вакуума. Верхняя граница не связана с высотой строительства мира.

По умолчанию относительная плотность около 0.794 на Y=300, 0.646 на Y=512, 0.392 на Y=1024 и 0.144 на Y=2048. Отрицательные высоты не дают бесконечного роста: сохранён потолок относительной плотности 1.5. Требуется `reference_height <= fade_start_height < ceiling_height` и положительный `scale_height`. При неверном сочетании параметров записывается предупреждение и сохраняется предыдущий корректный профиль. Настройки кэшируются при загрузке/изменении общего конфига; в расчёте поверхностей нет новых объектов или чтений конфига.

В Sable 2.0.6 `DimensionPhysics.createDefault` строит высотную кривую давления до `dimensionType.minY + dimensionType.logicalHeight`, заканчивая её нулём. Поэтому штатная атмосфера обрывается около верхней границы измерения. Наш mixin заменяет только вызов `BezierResourceFunction.evaluateFunction(Y)` внутри `DimensionPhysicsData.getAirPressure`. Базовое давление измерения по-прежнему умножается на новую кривую: измерение с базовым давлением 0 остаётся вакуумным. В выключенном режиме и вне списка `dimensions` вызывается исходная кривая. Это замена старой высотной функции, а не умножение уже обнулённого у Y≈300 результата. Формулы метода, который заменяет Lift Patch, не перезаписываются.

Проверка реального байткода обоих приложенных JAR подтверждает: одна выборка давления линейно умножает **нормальное сопротивление, ненаправленное сопротивление и подъёмную силу**. Падают все три, а не только lift. Таким образом, при прежней скорости лететь сложнее, а аэродинамическое сопротивление поверхностей меньше. При квадратичном росте подъёмной силы в обычном диапазоне снижение плотности вдвое требует примерно sqrt(2) прежней скорости для той же силы. Это приближение: Lift Patch использует мягкое насыщение `v² / (1 + v² / cap²)` для lift и нормального drag. Скоростью нельзя компенсировать произвольно низкую плотность; соответствующие soft caps и коэффициенты остаются настройками самого Lift Patch.

**Общее сопротивление не равно только сопротивлению крыльев.** Sable отдельно передаёт `universal_drag` в `PhysicsPipeline.init` при инициализации мира, без зависимости от давления/высоты (штатный default — 0.09). Этот глобальный механизм демпфирования сохранён и не становится слабее на высоте. Кроме того, винты Sable тоже запрашивают давление: разрежение может ослаблять их тягу. Поэтому снижение сопротивления крыльев подтверждено, но безусловный рост максимальной скорости любого самолёта не гарантируется: результат зависит от двигателя, демпфирования и soft caps. Новая кривая влияет на всех потребителей `getAirPressure`, в том числе винты и плавающие блоки, а не только паруса. Коэффициент `[wind].sail_pressure_coefficient` продолжает отдельно масштабировать силы поверхностей.

`testAtmosphere` проверяет 7 сценариев: нормировку, работу выше старого потолка, монотонность, непрерывность/касательные перехода, пользовательские высоты, точный вакуум и некорректные настройки. `scripts/check_atmosphere_hooks.py` сверяет высотную точку внедрения, сохранение базового давления, три умножения сил на давление в Sable и Lift Patch и отдельную инициализацию universal drag по реальным JAR. Игровой запуск и сравнение поведения самолётов здесь не выполнялись.


## Погодное зональное поле ветра

В `config/aste_aeroworks-common.toml`:

```toml
[wind.field]
dynamic = true
zone_size = 512.0
surface_height = 64.0
maximum_height = 250.0
surface_clear_speed = 2.5
surface_rain_speed = 4.0
surface_storm_speed = 6.0
aloft_clear_speed = 8.0
aloft_rain_speed = 12.0
aloft_storm_speed = 18.0
fallback_direction_interval_seconds = 360.0
weather_direction_interval_multiplier = 1.0
transition_seconds = 15.0
cloud_deviation_degrees = 15.0
```

Все скорости — блоки/сек, все высоты — абсолютные мировые Y. Между Y=64 и Y=250 направление и скорость плавно переходят от поверхностного к высотному слою. Выше Y=250 высотный множитель не растёт. Это выбор высоты без поиска рельефа: на высоких горах ветер тоже относится к высотному слою. Случайные изменения скорости в пределах ±15% дают около 2.1–2.9 блоков/с у нижнего слоя в ясную погоду. Коэффициент давления на паруса и высотное разрежение атмосферы продолжают действовать отдельно; скорость воздуха не равна силе на крыло.

Каждый узел сетки имеет воспроизводимую последовательность случайных целей от seed мира/измерения и координат; соседние узлы и соседние моменты времени смешиваются smoothstep. Сетка не создаёт блоков, чанков или постоянных объектов зон. Направления поверхностного и высотного слоёв отдельные; верхний следует фактическому перемещению массива Simple Clouds с суммарным отклонением до `cloud_deviation_degrees` от зонального рисунка и типа массива (каждый вносит не более половины этого угла). При отсутствии движения массива используется его заданное направление, а для SINGLE/отсутствующего массива — направление видимого движения шума, противоположное изменению scrollX/Z. `CloudManager.calculateWindDirection()` не используется как подмена фактического перемещения. Если облака неподвижны полностью, направление берётся из seed. Никаких вертикальных компонент не добавляется.

Тип облака, горизонтальная интенсивность осадков, `includesThunder` и `storminess` берутся из Simple Clouds **в позиции тела**, а не камеры или отдельного паруса. Дождь/гроза усиливают оба слоя; при недоступной погоде SC используется штатная погода мира. Смена id типа массива меняет целевые повороты обоих слоёв даже при одинаковой категории погоды и скорости; фактический ветер плавно догоняет цель. Отдельно продолжаются случайные зональные повороты. Их период привязан к среднему диапазону `CloudSpawningConfig.getSpawnInterval` с учётом скорости счётчика генератора (`max(1, ceil(cloudSpeed))`) и настраиваемого множителя. Это согласование масштаба времени, не предсказание точной даты фронта. Без расписания берётся fallback 360 секунд. При смене периода интегрируемая фаза не сбрасывается.

На серверном потоке погодные данные обновляются примерно раз в секунду на активное физическое тело с парусами/контрапциями. Лимит — 16 обновлений за тик, с обходом по кругу; при более чем 320 активных телах обновление может быть реже. Удалённые тела удаляются из следующего снимка; карты снимков не изменяются после публикации. Между снимками ветер вычисляется плавно по времени. В физическом потоке — только чтение снимков, простая математика сетки и переиспользуемый выходной буфер; нет обращений к CloudManager, шуму, генерации чанков или клиентскому renderer. Интеграция сохраняет одну выборку поля на тело за физический подшаг, включая вложенные поверхности. Изменения погодной цели во время перехода начинаются с текущего значения. Экспоненциальное сглаживание даёт около 95% реакции за transition_seconds; повторные обновления направления движущихся облаков не растягивают этот срок. При выходе из мира/остановке сервера кэш очищается.

Simple Clouds и CrackersLib теперь обязательны на обеих сторонах: сервер получает погоду из собственного CloudManager. Пользовательский `WindFields.setProvider` сохранён; результат ограничивается горизонтальными осями. Постоянный режим доступен для сравнительного теста. Указанные скорости — настраиваемые стартовые значения для балансировки, не измеренные в игре пределы.

`testZonalWind` добавляет 14 проверок: скорости нижнего слоя, усиление при погоде, высотный предел, согласование с облачным направлением, различия зон, непрерывность на положительных/отрицательных границах сетки и во времени, прерывание перехода, реакция на новый тип массива, самостоятельные случайные повороты, воспроизводимость, неверные настройки противоположные направления слоёв и независимость времени реакции от повторных обновлений направления облаков. CI дополнительно сверяет реально используемые серверные методы/координаты/направления и weather API по приложенному Simple Clouds 0.7.3. Полный игровой запуск ещё требуется.
