# Aero Works

Minecraft 1.21.1 / NeoForge 21.1.256. Клиентский туман внутри облаков Simple Clouds 0.7.3+1.21.1.

Туман учитывает позицию **камеры**, высоту облаков, тип и границы региона, слои шума, движение ветра и анимацию градиентов. Плотность рассчитывается на CPU по формуле `cube_mesh.comp` и MIT-алгоритму psrdnoise из приложенного JAR. Просветы и промежутки между слоями остаются прозрачными; режим AMBIENT, который убирает облака вокруг камеры, не создаёт туман. Чтения данных с GPU нет.

Обычная геометрия использует штатные цвет и сферические дистанции Minecraft fog через `ViewportEvent`, которые читает и Sodium. Дальность зависит от плотности: `visibility / strength`, с сохранением более короткого штатного тумана.

Дополнительный depth-aware проход выполняется в `GameRenderer` непосредственно после возврата `LevelRenderer.renderLevel`, перед рукой и HUD. Это гарантирует завершение tail-инъекций Simple Clouds и других модов; событие `AFTER_LEVEL` такой гарантии не давало. Матрица проекции сохраняется из фактических аргументов `LevelRenderer`, отдельно от матрицы DH.

Для DH откладывается штатный composite облаков до этого заключительного прохода. Непрозрачный цвет облаков и weighted transparency смешиваются с готовым изображением только перед ближней геометрией; сравниваются восстановленные расстояния из разных проекций. Это исправление направлено на дефект Sodium 0.8.x, при котором поздние чанки перекрывают ранее нарисованные облака. Экранный туман остаётся для DH и остальных рендереров, обходящих Minecraft fog. DH не становится обязательной зависимостью. Совместимость с Sodium 0.8.13 и Sodium Extra 0.9.3 пока требует проверки в игре.

Финальное копирование использует собственный `cloud_fog_copy` с заменой цвета (`ONE, ZERO`), а результат fog-pass имеет alpha=1. Альфа исходного main target не означает видимость сцены: небо и DH могут содержать корректный RGB при alpha=0. Ванильный `blit` со смешиванием `SRC_ALPHA` в очищенный main target стирал такие части изображения. Тесты проверяют оба прохода, включая нулевую и частичную альфу исходной сцены, вне облака и внутри него.

В воде, лаве и рыхлом снегу используются штатные эффекты. Эффект не увеличивает видимость уже затуманенной сцены. Обработчики и миксины загружаются только на клиенте. Состояние и ресурсы сбрасываются при выходе, смене мира и перезагрузке ресурсов; framebuffer и проекция восстанавливаются перед отрисовкой руки.

## Настройки

После первого запуска: `config/aste_aeroworks-client.toml`.

```toml
[cloud_fog]
enabled = true
# Дальность полной непрозрачности в плотном облаке, в блоках.
visibility = 24.0
# Ширина перехода по значению плотности шума.
boundary_width = 0.15
# Положительное значение включает туман раньше, в разреженной кромке облака.
density_offset = 0.0
# Время сглаживания в тиках, 0 отключает сглаживание.
transition_ticks = 3.0
# Раннее появление на внешней кромке без изменения полной плотности.
edge_density_margin = 0.15
# Серый цвет: яркость на кромке и внутри, относительно освещения облаков.
edge_fog_brightness = 0.9
dense_fog_brightness = 0.65
```

Для более раннего и быстрого срабатывания попробуйте `density_offset = 0.1`, `boundary_width = 0.05`, `transition_ticks = 1.0`. Для более густого тумана уменьшите `visibility`, например до 16. Теперь слабая плотность меняет прозрачность итогового тумана, а не смешивает дальность 24 блока с многокилометровой дальностью прорисовки.

При смене мира и дальних телепортациях состояние сбрасывается. Внутри закрытого самолёта/помещения эффект тоже работает: проверяется облако в позиции камеры, герметичность кабины пока не моделируется.

## Сборка и зависимости

`./gradlew build` (Windows: `gradlew.bat build`), JDK 21. Сборка использует JAR Simple Clouds из `libs`, API 1.4-1.21.1 и CrackersLib 1.21.1-0.4.6 из Maven автора. Для запуска клиента разработки Simple Clouds и CrackersLib подключены через `localRuntime`; API поставляется внутри Simple Clouds. При обычной установке установите Simple Clouds и CrackersLib отдельно — Aero Works не включает их в свой JAR.

Create и Sable уже лежат в `libs`, но для текущей функции не используются и не подключаются к classpath. Сборка нацелена на NeoForge 21.1.256, как основная сборка пользователя.

`check` запускает девять проверок периодичности шума, границ/пустот/слоёв облака, ветра, плавности при разном FPS и чувствительности, ранней кромки и серого цвета. CI также запускает `python3 scripts/test_cloud_fog_shader.py`: 22 проверок фактического fragment shader на программном OpenGL (Mesa/EGL), включая обычную геометрию, разные проекции Minecraft/DH и прозрачность при слабом облаке. Проверки не заменяют запуск полной сборки Minecraft.

## Проверка в игре

1. Полёт в плотное облако: дальность уменьшается примерно до 24 блоков, цвет соответствует облаку.
2. Выход из облака, полёт через просвет и выше/ниже слоёв: видимость восстанавливается.
3. Проверить движущееся облако, DEFAULT и SINGLE, вид от третьего лица, день/ночь и грозу.
4. Проверить воду/лаву, слепоту, смену измерения, отключение `cloud_fog.enabled` и `renderClouds` Simple Clouds.

Алгоритм совпадает с непрерывным полем шума Simple Clouds, но сам мод рисует облако кубическими ячейками и обновляет mesh с задержкой. Поэтому на поверхности возможна погрешность в несколько блоков; она смягчается переходом. Сторонние шейдерпаки и комбинация версий Sodium/Sable/Distant Horizons требуют проверки в игре: здесь протестирован shader, а полный игровой клиент не запускался.

## Идентификатор мода

ID Aero Works — `aste_aeroworks`. Имя JAR после сборки: `aste_aeroworks-1.0.0.jar`. Старый `aeroworks-1.0.0.jar` нужно убрать из папки `mods` перед установкой нового. ID `aeroworks` принадлежит другому моду, который могут требовать Gadgets ’n Gizmos и Create Thrusters; Aero Works не заменяет эту зависимость. Если ранее менялись параметры нашего тумана, перенесите их из `aeroworks-client.toml` в `aste_aeroworks-client.toml`.

Новые настройки `edge_density_margin`, `edge_fog_brightness`, `dense_fog_brightness` автоматически добавляются и в существующий конфиг. Расширенная кромка начинается раньше, но достигает полной силы в той же точке плотности, что и раньше; `visibility` и верхняя граница силы остаются прежними. Цвет обоих путей рендеринга одинаков: яркость облаков переводится в серый и умножается на плавный коэффициент от 0.9 до 0.65 по силе тумана.

При выборе расстояния тумана пиксель обычной поверхности имеет приоритет над смешанным буфером DH/облаков. DH используется для пикселей без обычной поверхности, а реально нарисованное непрозрачное облако перед поверхностью может перекрыть её. Скрытая LOD-геометрия не должна менять туман поверх обычного чанка. Три дополнительные OpenGL-проверки сравнивают туман земли при изменении глубины скрытого LOD и сохраняют туман на видимом LOD без обычных чанков.
